# Tech Stack, API Schema and Packaging Requirements

Part of the spec set indexed in [`req.md`](./req.md). Requirements only.

## Decisions

| # | Decision |
| :-- | :--- |
| D24 | The API is built with **FastAPI** (Python), the stack already used in `app/`. |
| D25 | The API schema is published in **OpenAPI** format and is the contract for the CLI, the later UI, and tests. |
| D26 | The API is deployed from its **own Helm chart in `charts/api-service/`**, separate from the service code. Charts stay standalone; no umbrella or library chart for now. |
| D27 | Kubernetes is reached through a **port and adapter**: the use cases depend on a `ClusterPort` interface, and a Kubernetes adapter implements it. |

## Stack

| # | Requirement |
| :-- | :--- |
| F1 | **FastAPI** on **Python 3.12** (matches the repo's virtual environment), served by uvicorn. |
| F2 | **Pydantic models** define every request and response body. They are the single validation layer (V8) and the source of the OpenAPI schemas. |
| F3 | **Kubernetes access** uses the official `kubernetes` Python client, inside the adapter (D27), as validated in [`../docs/python-client-coverage.md`](../docs/python-client-coverage.md). It is synchronous, so handlers that call it are plain `def` (run in FastAPI's threadpool), not `async def`. |
| F4 | **Authentication** is one global dependency (A2), modelled on the earlier `app/auth.py` (deprecated; the API has its own `auth/` package) with the fixes in [req-auth.md](./req-auth.md). |
| F5 | **Observability** uses the OpenTelemetry Python SDK ([req-observability.md](./req-observability.md)). **Tests** use pytest ([req-tests.md](./req-tests.md)). |
| F6 | **Dependencies are pinned** to exact versions in a requirements file, and the image tag is pinned (`AGENTS.md`). |
| F7 | The CLI is also Python, in the same repository (assumption), and talks to the API only over HTTP (U6). |

## OpenAPI schema (D25)

| # | Requirement |
| :-- | :--- |
| F8 | The schema is an **OpenAPI 3.1** document generated by FastAPI from the code (code-first), and exported to `control-plane/spec/openapi.yaml`, committed to the repository. |
| F9 | **No drift.** A test regenerates the document and fails if it differs from the committed file. A `make` target regenerates it. |
| F10 | The document describes every `/api/v1` endpoint, all request and response models, and a `bearerAuth` security scheme (HTTP bearer, JWT) applied to every protected operation. |
| F11 | **Error responses are documented as the API returns them:** 400 (not FastAPI's default 422), 401, 403, 404, 409, 429 and 500, each using one shared `Error` schema (`error.code`, `error.message`, `error.details[]`, `request_id`). The default 422 response is removed from the schema. |
| F12 | Each operation has a stable `operationId`, a summary, tags by category, and at least one request or response example (the `http-echo` example in the assessment style). |
| F13 | The document states the API version `1.0.0` (P6) and is served at `/openapi.json` only in dev, or behind authentication (R23). The committed file is the copy reviewers read. |
| F14 | Enumerations in the schema match the spec: health values (`HEALTHY`, `DEGRADED`, `FAILING`, `PROGRESSING`, `UNKNOWN`), pod phases, and container states. |
| F15 | The OpenAPI file passes a linter (for example Spectral or `openapi-spec-validator`) in CI. |

## Deployment packaging (D26)

| # | Requirement |
| :-- | :--- |
| F16 | **Chart location.** `charts/api-service/` holds `Chart.yaml`, `values.yaml`, `values.schema.json` and `templates/`. `control-plane/api-service/` holds code, tests and docs only. There is no `.infra/` folder inside the service. |
| F17 | **Layering** (`AGENTS.md`): chart defaults, then `environments/base.yaml`, then `environments/<env>/api-service.yaml` (deltas only). Credentials go in `environments/<env>/api-service.secrets.yaml` (gitignored); only `*.secrets.example.yaml` is committed (K3). |
| F18 | **Tooling.** The Makefile and `scripts/*.sh` take `CHART=<name>` (default `app`). `make lint` and `make render-all` cover every chart, so CI checks both. Release and namespace default to `<chart>-<env>`, for example `make deploy-dev CHART=api-service`. |
| F19 | **One source for RBAC.** The ClusterRole, binding and per-namespace Roles (R11, R12, R14) are chart templates. Cluster-scoped names carry the release name. One Role is rendered per entry of `allowedNamespaces`, and those namespaces must exist at install time. |
| F20 | **Schema guards.** `values.schema.json` rejects `MOCK_AUTH_ENABLED=true` outside dev (see req-config.md assumption 4), `latest` image tags, a relaxed security context, wildcard CORS origins, invalid namespace names, and unknown setting names. |

### Why this shape

- Descriptors stay separate from service code because more microservices are expected and may later ship together. Each chart is standalone, so it can be composed later without moving files.
- **Deferred:** an umbrella chart, a shared library chart (`charts/common`), Helmfile or Argo CD. Each adds value only once there are several services. Nesting values under a subchart name would also force `environments/base.yaml` under `global:`.
- **Rejected:** `.infra/` inside the service. It ties deployment to one service's folder and hides the chart in a dot directory.

## Cluster access: port and adapter (D27)

| # | Requirement |
| :-- | :--- |
| F21 | **Port.** `ports.py` defines `ClusterPort`, a `typing.Protocol` with the operations the use cases need (namespaces, secret labels, deployments, pods, ping). Arguments and results are plain dicts, strings and the domain snapshots in `domain.py`. It names no SDK type. `service.py` and the controllers import the port, never the adapter. |
| F22 | **Adapter.** `KubernetesAdapter` in `kube.py` implements the port with the official client (F3). It is the only module that imports the SDK. It converts SDK objects to snapshots and SDK errors to `KubeFailure` kinds (R24), and caches nothing (N1). |
| F23 | **Contract for any adapter.** The only exception that leaves it is `KubeFailure` with a fixed kind (`not_found`, `conflict`, `unreachable`, `forbidden`, `other`). Results are live and managed-only (D2). |
| F24 | **Wiring.** The adapter is chosen once, in `create_app` (the composition root), and injected. Unit tests inject a fake adapter (Q1). |
| F25 | **Tests.** Every adapter, including the fake, must match the port's method names, parameters and defaults. No module except `kube.py` may import the SDK, and the application layer may not import `kube.py`. Both are tests (`test_cluster_port.py`). |

Why: the sync client, its error types and its object model stay in one file, the fake in tests is checked against the real interface, and another backend (a different client library, a recorded cluster) is a new adapter with no change to the use cases. The port is SDK-free but not Kubernetes-free: `create_deployment` and `patch_deployment` still take Kubernetes-shaped manifest dicts from `builder.py`.

## Consequences

- FastAPI maps body validation errors to 422 by default; F11 requires a handler that returns 400 (V2) and a schema that says so.
- The sync Kubernetes client limits concurrency to the threadpool size, which also caps concurrent log streams (R21).
- Helm cannot label the release namespace, so the `pod-security.kubernetes.io/enforce: restricted` label (previously in `deploy/rbac.yaml`) must be set when the namespace is created. The pod spec already complies; the label is defence in depth.
- The chart references the image `api-service:1.0.0`. The Dockerfile for it is not built yet, so a live deploy needs that first.

## Assumptions to confirm

1. Code-first generation (F8) rather than writing the YAML by hand first.
2. The CLI is Python (F7); no CLI framework chosen.
3. The schema is exported as YAML at `control-plane/spec/openapi.yaml`.
4. Python 3.12 is the minimum supported version.
